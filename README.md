# Codex Connect

Русский | [English](docs/README.en.md) | [简体中文](docs/README.zh.md)

## Краткое описание

Независимый форк Codex Connect добавляет OAuth-вход через ChatGPT и провайдера моделей `openai-codex` для [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness). Сессиями, инструментами и разрешениями управляет DSH; плагин отвечает за подключение Codex, выбор аккаунта и дополнительные функции.

Проект находится в стадии Alpha и поддерживается сообществом. Он не связан с OpenAI, ChatGPT, Codex, DeepSeek или DeepSeek Harness. Подписка ChatGPT не является ключом OpenAI Platform API.

## Установка и запуск

Текущая версия форка — `0.2.0-alpha.4.1`; проверенная пара для неё — DSH `0.2.1-alpha.4`. Для других сочетаний версий совместимость не подтверждена. Устанавливайте именно этот форк из публичного GitHub-репозитория [`tonulls/dsh-codex-connect`](https://github.com/tonulls/dsh-codex-connect/tree/tonulls), в тот профиль, с которым запускаете DSH.

Требования: Node.js `^22.19.0` или `>=24.0.0`; установленный DSH. Эта ветка обновляется, поэтому установка из неё получает текущее состояние `tonulls`, а не неизменяемую версию из npm.

1. Убедитесь, что команда `dsh` доступна, а DSH использует нужный профиль. В примере это `web`.
2. Установите плагин из ветки `tonulls`:

   ```sh
   dsh plugin --profile web add 'git+https://github.com/tonulls/dsh-codex-connect.git#tonulls'
   ```

   Установка из GitHub собирает плагин. Если pnpm сообщает, что скрипты сборки зависимостей пропущены, добавьте в `allowBuilds` только пакеты, которые указаны в сообщении DSH, затем повторите установку.

3. Запустите веб-интерфейс с тем же профилем:

   ```sh
   dsh web
   ```

4. В DSH откройте **Настройки → Плагины → Конфигурация плагинов → Codex Connect**, выполните авторизацию в открывшемся браузере и выберите активный аккаунт. Затем выберите модель `openai-codex` в селекторе моделей.

Замените `web` на имя своего профиля во всех командах. OAuth-данные находятся на машине с DSH, поэтому используйте тот же профиль и каталог данных, где уже хранятся ваши аккаунты. Не публикуйте ссылку авторизации, коды, токены или идентификаторы аккаунтов.

## Проверка и диагностика

<details>
<summary>Показать команды проверки и диагностики</summary>

Проверьте версию DSH и состояние плагина:

```sh
dsh --version
dsh plugin --profile web exec dsh-codex-connect status --json
dsh plugin --profile web exec dsh-codex-connect doctor --json
```

`status --json` сообщает, выполнен ли вход, и не запускает OAuth. `doctor --json` проверяет локальную установку без сетевого запроса и не выводит исходные OAuth-секреты. Если плагин не появился в DSH, проверьте, что команды используют нужный профиль, а установка из Git завершилась без ошибки сборки.

Перед отправкой вывода команд удалите адреса аккаунтов и любые секреты. Подробности — в [справочнике диагностики](docs/reference.md).

</details>

## Остановка и удаление

<details>
<summary>Показать, как остановить DSH или удалить плагин</summary>

- Если DSH запущен в терминале, остановите его сочетанием `Ctrl+C`.
- Если DSH запущен расширением VS Code, используйте команду остановки DSH в панели или строке состояния расширения.
- Чтобы удалить только плагин из профиля `web`, выполните:

  ```sh
  dsh plugin --profile web remove dsh-codex-connect
  ```

Удаление плагина не удаляет сессии DSH и сохранённые OAuth-аккаунты. Не запускайте `logout` и не удаляйте файлы профиля, если хотите сохранить авторизацию. Выход из всех аккаунтов — отдельное действие, которое стирает сохранённые OAuth-данные.

</details>
