# Возможности и настройки Codex Connect

Эта страница содержит подробности, вынесенные из основного README. Краткие инструкции установки находятся в [главном README](../README.md), полный справочник — в [reference](reference.md).

## Аккаунты и модели

- Плагин может хранить до 16 OAuth-аккаунтов на машине с DSH. Активный аккаунт выбирается вручную; автоматической ротации и незаметного переключения нет.
- Выбранный аккаунт применяется к последующим запросам и не закрепляется за отдельной сессией.
- Проверенная комбинация этого форка и DSH поддерживает `gpt-6-astra` с уровнями рассуждения Low, Medium, High, Xhigh и Max. Наличие модели в списке не гарантирует права аккаунта на её использование.
- Fast Mode — опциональный приоритетный режим для разговоров. Он выключен по умолчанию; скорость и расход квоты определяются сервисом.
- Интерфейс показывает квотные окна `5h` и `7d`, возвращённые сервером. Отсутствующие значения не подменяются предположениями.

## Необязательные функции

Новые необязательные настройки по умолчанию выключены. Их можно менять в **Настройки → Плагины → Конфигурация плагинов → Codex Connect** или **Настройки → Модели → Openai-Codex → Дополнительные настройки**. После изменений сохраните настройки.

| Функция | Параметр | Поведение |
|---|---|---|
| Прокси | `enableProxy` | HTTP(S)-прокси используется только для запросов этого плагина. Ошибка прокси не вызывает незаметный переход на прямое соединение. |
| Поиск Codex | `enableSearch` | Переключает поисковый маршрут профиля на Codex; выключение восстанавливает предыдущий маршрут. |
| Luna Reserve | `enableReserveFallback` | Скрытый Reserve используется только при явном разрешении сервера для выбранного аккаунта. Не меняет модель по умолчанию и не повторяет произвольный `429`. |
| Просмотр изображений | `enableImageTool` | Добавляет `view_image` для локальных файлов и проверенных публичных HTTP(S)-изображений. |
| Генерация и редактирование | `enableImageGeneration` | Позволяет создавать изображения и редактировать явно выбранные изображения разговора. Доступность, размеры и квоты зависят от аккаунта и сервиса. |
| Автоматическая проверка | `enableAutoReview` | Передаёт ограниченный контекст действия на проверку в ChatGPT после того, как политика Harness потребовала подтверждение. Не обходит подтверждения Harness; при ошибке управление возвращается человеку. |

## Хранение и восстановление

OAuth-данные хранятся на машине, где работает DSH, в `$DSH_HOME/.openai-codex-auth.json` (обычно `~/.dsh`). Плагин не копирует и не изменяет `~/.codex/auth.json`. Удаление самого пакета не удаляет OAuth-данные, сессии DSH или сохранённые результаты генерации изображений. Команду `logout` используйте только если действительно хотите удалить авторизацию.

При отмене новой авторизации существующие аккаунты сохраняются. Временные ошибки обновления токена сами по себе не удаляют аккаунт. Подробнее — в разделах [аккаунты и квоты](reference.md#accounts-models-and-quota) и [поиск и изображения](reference.md#search-and-image-tools).

## Частые вопросы

### Почему модель отображается, но запрос завершается ошибкой?

На доступ влияют права аккаунта, совместимость версий DSH и плагина, сеть и состояние сервиса. Запись модели в каталоге не подтверждает наличие доступа. Проверьте точную совместимость и выполните `doctor --json`.

### Можно ли назначить отдельный аккаунт каждой сессии?

Нет. Активный аккаунт применяется к последующим запросам профиля, а не привязывается к конкретной сессии. Fast Mode настраивается для разговора отдельно.

### Как перенести аккаунты?

OAuth-аккаунты хранятся в DSH home на хосте, где запущен DSH. Используйте тот же профиль и каталог данных; не копируйте и не публикуйте файлы авторизации вручную. Для Desktop и Web могут использоваться разные профили.

### Можно ли оставить установленным старый `dsh-codex`?

Нет, если оба плагина активны в одной конфигурации: они регистрируют один и тот же `openai-codex` provider. Следуйте [руководству по миграции](MIGRATION.md) и удаляйте только подтверждённую конфликтующую запись, не OAuth-файлы и не посторонние плагины.

### Что подтверждает локальная диагностика?

`doctor` проверяет локальную конфигурацию и зависимости. Диагностика сама по себе не подтверждает доступ к модели. Некоторые отдельные проверки возможностей могут обращаться к сети и использовать квоту; перед их запуском читайте соответствующие ограничения в [справочнике](reference.md).
